# Releasing macron

A release is a tag. Pushing `vX.Y.Z` runs the Release workflow (`.github/workflows/release.yml`,
generated by [dist](https://opensource.axo.dev/cargo-dist/) from `dist-workspace.toml`), which:

1. builds `macron` for Apple silicon and Intel Macs;
2. publishes a GitHub release with both builds, a shell installer and checksums, its notes taken
   from the version's entry in `CHANGELOG.md`;
3. publishes `macron-cli` to crates.io (`.github/workflows/publish-crates.yml`).

A version with a pre-release suffix, such as `v0.2.0-rc.1`, gets a GitHub pre-release and nothing
else.

## Steps

1. With everything for the release merged to `main`, run the test against the real launchd on a
   Mac: `cargo test --test launchd -- --ignored`.
2. On a branch, set `version` in `Cargo.toml` and run `cargo check` to update `Cargo.lock`. Before
   1.0, a breaking change (a `!` commit) bumps the minor version, and anything else the patch.
3. Draft the changelog entry with [git-cliff](https://git-cliff.org):

   ```sh
   git cliff --unreleased --tag vX.Y.Z --prepend CHANGELOG.md
   ```

   It lists the `feat`, `perf` and `fix` commits since the last tag. Then edit it for someone using
   macron: join commits that are one change, drop fixes to things never released, and say what a
   breaking change means for them. Set the date to the day you will tag.
4. Commit it as `chore: release vX.Y.Z`, open a pull request, and merge it once CI passes. Its
   `plan` check shows what the release will build.
5. Tag the merge commit and push the tag:

   ```sh
   git switch main && git pull
   git tag vX.Y.Z && git push origin vX.Y.Z
   ```

6. When the Release workflow is done, install the release as a user would, with the installer
   command in the README, and run `macron --version` and `macron doctor`.

## When something goes wrong

- **Never move or reuse a tag that was pushed.** A version on crates.io is permanent. Fix forward
  with a new patch version.
- **The crates.io job failed.** The GitHub release exists by then. Fix the cause and re-run the failed
  job from the workflow's page.
- **An authentication error from crates.io** means the `CARGO_REGISTRY_TOKEN` secret on
  `realzai/macron` has expired. Replace it with a crates.io token with the `publish-update` scope
  for `macron-cli`.

## Changing how releases are made

Edit `dist-workspace.toml`, then run `dist generate` and commit the rewritten `release.yml`. To
update dist itself, install the new version and run `dist init`. The `plan` check fails on a pull
request whose `release.yml` does not match the configuration.
